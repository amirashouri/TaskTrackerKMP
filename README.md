# TaskTracker

A task and project tracker for **Android and iOS**, built as a Kotlin Multiplatform
port of an original SwiftUI application. One shared Compose UI, one shared domain,
Clean Architecture boundaries enforced by the compiler rather than by convention.

## What's in it

- **Auth** — sign-in against a Ktor-backed API, JWT session, token refresh with a
  single-replay guard, offline-first error mapping.
- **Projects** — a project list, a per-project **board** of columns, and a
  **backlog** projection.
- **Work items** — creation and editing in a shared editor, dependency links,
  status transitions.
- **Sprints** — sprint list, detail, and summary screens with progress totals.
- **Settings** — theme choice (light/dark/system), user details, version info.
- **Sync** — Room-backed local store with an outbox queue; mutations are queued
  locally and reconciled with the server.

## Tech stack

| Layer | Choice |
| --- | --- |
| UI | Compose Multiplatform 1.12.1, shared across Android + iOS |
| Architecture | Clean Architecture — domain / data / presentation modules, `:composition-root` binds them |
| Local storage | Room (KMP) |
| Networking | Ktor 3.6.0 (OkHttp on Android/JVM, Darwin on iOS) |
| Serialization | kotlinx.serialization, strict JSON coding |
| Design | "Liquid Glass" token system in `:packages:design-system` |
| Build | Gradle + convention plugins; XcodeGen for the iOS shell |

The module graph is not a suggestion: `verifyArchitectureGraph` and
`verifyModuleImports` are build tasks that fail on a dependency edge the
architecture does not allow.

## Project layout

```
androidApp/                  Android entry point
iosApp/                      Xcode shell (generated by xcodegen — do not hand-edit)
shared-ui/                   The shared Compose screen tree
composition-root/            Object graph — the one module that sees everything
packages/
  core/                      Logging, errors, JSON coding, JWT
  domain/                    Domain models and ports
  database/                  Room schema, DAOs, outbox
  network/                   Ktor client, interceptors, retry
  sync/                      Outbox reconciliation
  design-system/             Liquid Glass tokens, components, strings
  feature-<name>-{domain,data,presentation}/   One triple per feature
build-logic/                 Convention plugins that define the architecture
docs/DECISIONS.md            The design record — why each rule exists
docs/TEST-HOSTS.md           Pre-existing test failures and host-specific gotchas
Project.md                   How to build, run, and verify
```

## Requirements

- **JDK 25** — point Gradle at Android Studio's JBR if nothing else is installed:

  ```bash
  export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
  ```

- **Xcode** (for the iOS target) with at least one iOS simulator.
- **XcodeGen** (`brew install xcodegen`) — regenerates the iOS project from
  `iosApp/project.yml`; the `.xcodeproj` is deliberately not committed.

## Running

### Android

Open the project in Android Studio, select the **`androidApp`** run configuration,
pick an emulator or device, run. The Compose resources are packaged into the APK's
assets by a hand-wired task (see the comment in `androidApp/build.gradle.kts` — the
plugin's own wiring is silently broken on this AGP).

### iOS

```bash
cd iosApp && xcodegen generate
```

Then open `iosApp/TaskTracker.xcodeproj` in Xcode (or the **`TaskTracker`** run
configuration in Android Studio) and run on a simulator. A build phase links the
Gradle-built `ComposeApp.framework`, so the Kotlin side is rebuilt automatically —
but the app always links whatever is already at the framework path, so a green Xcode
build does not mean the Kotlin you just edited is in it; check the Gradle task output.

## The command that decides whether you are done

```bash
scripts/check.sh
```

It compiles the Android app, checks the architecture graph, and runs the JVM and iOS test
hosts. `Project.md` lists the scopes (`jvm`, `ios`, `android`, `graph`, `lint`, `docs`) and
the extras that are known-red.

Tests run on **three hosts**: the JVM, the iOS simulator, and Android under
Robolectric. The Android host is deliberately stricter about some things and weaker
about others (Robolectric's viewport is small; its `Build` fields are `null`) —
`Project.md` records the exact split and which failures are known and documented.
