# 7.5 — Subsurface scattering horizontal gradient on wide cards

- **status:** done
- **priority:** P2
- **plan:** [`docs/PLAN.md`](../docs/PLAN.md) §7, entry `7.5`

## Scope

Modules: `packages:design-system` (Glass.kt only).
Layers: Design system primitive (`ttGlassSurface` drawBehind).
Single-module change — fast path per `AGENTS.md` (one package, no public API change).

## Files

- `packages/design-system/src/commonMain/kotlin/com/tasktracker/designsystem/Glass.kt` — modified `ttGlassSurface` drawBehind to add horizontal radial gradient on wide cards (width > 2 * height).
- `packages/design-system/src/commonTest/kotlin/com/tasktracker/designsystem/GlassSurfacePixelTest.kt` — added tests for wide card (400x150) verifying center-to-edge brightness difference (≥ 2 channels).

## Contract

- [x] On surfaces where `width > 2 * height`, a subtle radial gradient centered at top-center fades toward edges.
- [x] Effect: center of top edge slightly brighter than corners (simulates light entering top, scattering toward sides).
- [x] Subtle: alpha 0.025 at center, 0 at edges.
- [x] Only applies when `base == null` (unbased glass fill, not lens).
- [x] Tall cards (height ≥ width/2) unchanged.
- [x] Pixel test: render 400x150 card, verify center top edge ≥ 2 channels brighter than corners.

- Run: focused JVM tests for the touched modules (under a minute); the three-host run is the release gate: `scripts/check.sh full` (all three hosts; pixel tests required)
- Counts: `test-baseline.json` gains 2 new test cases (light + dark wide card).
- Pixel-reading test: `GlassSurfacePixelTest` — passes on both hosts.

## Handoff

- **Done:** Implementation complete. All three hosts pass (JVM 2004, iOS 1950, Android 1646 tests). Baseline regenerated (+2 tests).
- **Pending:** None.
- **Next step:** Task 7.6 (Chromatic aberration at rim) or any other P3 task.
- **Gotchas:** The radial gradient uses `BlendMode` default (src-over) since `BlendMode.Plus` not available in commonMain. White at 0.025 alpha naturally brightens. Only activates on wide cards (aspect ratio > 2:1). iOS and JVM both pass with 2-channel minimum delta.

## Risks / notes

- Current `fillRamp` is purely vertical. Added horizontal component as second draw pass in `drawBehind`.
- iOS and JVM rasterizers agree on the effect — both measure ≥ 2 channel delta.
- The effect is subtle; pixel test measures channel difference at top-center vs top-corner.
- Only activates on wide cards (aspect ratio > 2:1), so existing tall-card tests unchanged.
