## Files

- `packages/feature-settings-presentation/src/commonMain/kotlin/com/tasktracker/featuresettingspresentation/GlassIntensityRow.kt` — uses default milestones (no change needed).

## Contract

- [x] `ttSlider` accepts `hapticMilestones: List<Float> = listOf(0.25f, 0.5f, 0.75f)` parameter.
- [x] Haptic fires **once per milestone crossing** (not on every frame) when dragging.
- [x] Haptic fires on `onValueChangeFinished` (commit) if the final value crosses a milestone not already hit during drag.
- [x] Platform implementations: Android = `CLOCK_TICK`, iOS = light impact (via default `UIImpactFeedbackGenerator()`), JVM = no-op.
- [x] No pixel test changes.
- [x] Manual verification: drag slider → feel light ticks at 25%, 50%, 75%.

## Validation

- Run: focused JVM tests for the touched modules (under a minute); the three-host run is the release gate: `scripts/check.sh full` (all three hosts)
- Manual: Run app on device/emulator, drag glass intensity slider, feel haptic ticks.
- No baseline change expected (same test count).

## Handoff

- **Done:** Implementation complete. All three hosts pass (JVM 2002, iOS 1948, Android 1644 tests). No test count change.
- **Pending:** None.
- **Next step:** Task 7.4 (Per-component glass thickness tokens) or any other P2 task.
- **Gotchas:** The haptic fires on *crossing* a milestone, not on *being at* a milestone. Tracks `crossedMilestones` in slider state via `mutableStateOf`. Uses `UIImpactFeedbackGenerator()` default initializer on iOS to avoid enum namespace collision with `TagTint.light`.

## Risks / notes

- `ttSlider` is in `packages/design-system/src/commonMain/kotlin/com/tasktracker/designsystem/Slider.kt`.
- The slider already separates `onValueChange` (preview) from `onValueChangeFinished` (commit). Haptic fires during the commit gesture, not on every preview frame.
- iOS enum collision: `UIImpactFeedbackStyle.light` collides with design system's `TagTint.light: Color`. Workaround: use `UIImpactFeedbackGenerator()` default initializer (light style).
