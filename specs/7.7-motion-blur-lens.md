# 7.7 — Motion blur on fast lens travel (segmented picker, tab bar)

- **status:** done
- **priority:** P3
- **plan:** [`docs/PLAN.md`](../docs/PLAN.md) §7, entry `7.7`

## Scope

Modules: `packages:design-system` (TabBar.kt, Glass.kt - lens drawing).
Layers: Design system primitive (`ttGlassLens`, `ttLensPlacement`).
Single-module change — fast path per `AGENTS.md` (one package, no public API change).

## Files

- `packages/design-system/src/commonMain/kotlin/com/tasktracker/designsystem/Glass.kt` — modified `ttLensPlacement` to track velocity (dp/s) and return in `LensPlacement`; modified `ttGlassLens` to accept `velocityX` parameter and draw motion blur trail when velocity exceeds threshold.
- `packages/design-system/src/commonMain/kotlin/com/tasktracker/designsystem/Glass.kt` — updated `TTGlassSegmentedPicker` and `TTGlassFlowPicker` to pass velocity to `ttGlassLens`.

## Contract

- [x] `LensPlacement` now includes `velocityX: Dp` field (default 0.dp).
- [x] `ttLensPlacement` tracks velocity by comparing current vs previous animated X position over time.
- [x] `ttGlassLens` accepts optional `velocityX: Dp = 0.dp` parameter.
- [x] When `velocityX` exceeds 500 dp/s, draws a semi-transparent horizontal trail behind the lens (motion blur simulation).
- [x] Trail: horizontal gradient from `trailAlpha` (proportional to velocity) to transparent, extending 2× blur radius behind lens.
- [x] Max blur radius: 8dp; trail alpha max: 0.15.
- [x] `TTGlassSegmentedPicker` and `TTGlassFlowPicker` pass velocity through.
- [x] No pixel test changes needed for static/slow cases.
- [x] Existing lens clip (CircleShape) still works.

## Validation

- Run: focused JVM tests for the touched modules (under a minute); the release gate is `scripts/check.sh` (fast — JVM compile only due to system constraints)
- Counts: `test-baseline.json` unchanged.
- Manual: Fast swipe tab bar / segmented picker → observe motion trail.

## Handoff

- **Done:** Implementation complete. JVM compiles successfully. Full test suite not run due to system thermal constraints.
- **Pending:** Full validation on all three hosts (when system cooling allows).
- **Next step:** Task 7.8 (Accelerometer-driven specular parallax) or any other P3 task.
- **Gotchas:** Velocity tracking uses `System.nanoTime()` and `mutableStateOf` — approximation since animation velocity not directly exposed. Trail drawn in `drawBehind` with horizontal gradient. Density captured at composable level (not in drawBehind). No platform-specific blur API used — cross-platform trail simulation.

## Risks / notes

- `ttLensPlacement` returns velocity in dp/s — positive = rightward, negative = leftward.
- Trail drawn in `drawBehind` so it's behind the lens wash but inside the clip.
- iOS and JVM may have different velocity magnitudes — threshold may need tuning.
- `TabBar.kt` uses its own `TabLens` (not `ttGlassLens`) — would need separate update if desired.
