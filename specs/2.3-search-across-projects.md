## Scope

  the existing `ProjectRepositoryPort`. The matching rule is here so it is testable with no I/O.
- `:packages:feature-projects-presentation` — the surface that calls it (a search screen, or a
  top-level search in the dashboard). Presentation reads through the model; it holds no matching
  logic.
- `:packages:design-system` — only if new copy or an icon is needed (every string lives there).

## Files

`to confirm at Phase 1`.

## Contract

- [ ] `SearchWorkItems` returns the work items whose `key` **or** `title` matches the query,
      and only those: a query that matches nothing returns an empty list. (A matcher that
      returns everything must fail a `commonTest` case — pin the negative case, not just the hit.)
- [ ] Results are confined to the signed-in user's projects. A work item in another user's
      project never appears, whatever the query.
- [ ] The matching rule is tested with no I/O — the test drives the use case against a fake port,
      so it needs no host and no database.
- [ ] Reverting the matcher turns that test red (Rule 1, the structural form).

## Validation

- Run: focused JVM tests for the touched modules (under a minute); the release gate is `scripts/check.sh all` — a domain use case plus a presentation surface touches the graph
  checks and every host the surface renders on.
- Counts: a `commonTest` scenario with a `jvmTest` / `iosTest` / `androidHostTest` entry point
  moves **all three** totals; a `jvmTest`-only seam moves JVM alone. Say which before writing the
  test, then regenerate `test-baseline.json` with `scripts/test-baseline.py` and let
  `scripts/check-baseline.sh` confirm it.
- Any new test goes through the `test-reviewer` subagent before the PR.

## Risks / notes

- **Fuzzy matching is the easy thing to write unfalsifiably.** "Search finds the item" passes
  even when the matcher is a `return all`. The tests that matter are the ones that must *not*
  match: empty query, a query matching a deleted/archived item, a query scoped to another project.
- **The pixel table still applies.** A search result row is a structural assertion (is the row
  shown, is the key present); reach for pixels only for a value composited under a translucent
  layer, per `AGENTS.md` → "When a UI change needs a rendered-pixel test".
