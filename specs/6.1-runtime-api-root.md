# 6.1 — Runtime API root override

- **status:** pending
- **priority:** P0
- **plan:** [`docs/PLAN.md`](../docs/PLAN.md), entry `6.1`; detailed rationale:
  [`docs/PLAN-ARCHIVE.md`](../docs/PLAN-ARCHIVE.md) §6. The active index is
  the *what*; this file is the *how*.

## Scope

`:composition-root` (the URL resolution) and `:packages:user-defaults` (the key). No
network change, no wire-format change, no Room change. The server half is
`TaskTrackerServer` `T9.7`.

## Files

To confirm at Phase 1.

- `packages/user-defaults/.../PreferencesBackend.kt` — a new `DefaultsKey` for the API
  root. It is a **preference, not a credential**, so it belongs here beside
  `LastSeenProject` and not in `KeychainKey`. The value is a URL, which is not a secret.
- `packages/user-defaults/.../UserDefaultsStore.kt` — only if the new key needs a raw
  (non-`DefaultsKey`) accessor; prefer the enum so sign-out's `clear()` walk covers it.
  **Check this first:** `clear()` walks `DefaultsKey.entries`, so a server override stored
  under the enum is cleared on sign-out. That is the wrong behaviour — a customer should
  not have to re-enter their server address after signing out. If so, this is the case
  for the existing raw-key path, and the spec must say which and why.
- `composition-root/.../PlatformApiBaseUrl.kt` — the resolution order: persisted override,
  then the platform's build-time value, then `DEFAULT_LOCAL_API_BASE_URL`.
- `composition-root/.../PlatformApiBaseUrl.{jvm,ios,android}.kt` — no signature change
  expected; confirm, because an `expect` change obliges all three actuals in the same
  transaction.
- `composition-root/src/commonTest/.../PlatformApiBaseUrl*Test.kt` — the new precedence.

## Contract

- [ ] With no override, every host returns exactly what it returns today — the three
      existing `PlatformApiBaseUrl` tests stay green and unmodified.
- [ ] A persisted override wins over the build-time value on all three hosts.
- [ ] A blank or whitespace-only override is treated as unset and falls back, matching the
      existing `takeIf { it.isNotBlank() }` rule; it must not produce a `URLBuilder` with
      no scheme.
- [ ] The override survives sign-out (the decision above), and the test names that
      explicitly — a change that moved it into `DefaultsKey` would otherwise pass a
      "persists" test and fail this one.
- [ ] Removing the override restores the build-time value without an app restart, or the
      spec records that a restart is required and why.
- [ ] The override is part of what `platformApiBaseUrl` returns, so the existing local-network
      classification and the Android permission request cover it. An override saved to
      `10.0.2.2`, an RFC1918/CGNAT address or an mDNS name must not produce a silent timeout —
      see [`android-local-network-permission.md`](android-local-network-permission.md).

## Validation

- Run: `scripts/check.sh` and `scripts/check.sh full` — this touches `expect`/`actual` and
  `:composition-root`, so all three hosts are required, not just JVM.
- Counts: `test-baseline.json` moves on the hosts where the new tests live; regenerate with
  `scripts/test-baseline.py` and let `scripts/check-baseline.sh` pass.
- Mutation check: with the override branch removed, the precedence test must fail naming
  the build-time value it got instead.

## Handoff

- **Done:** the PLAN entry only. No code.
- **Pending:** the ACK (2+ modules, public API), then the `DefaultsKey` decision — enum vs
  raw key — which is the one design question in the task.
- **Next step:** read `UserDefaultsStore.clear()` and decide. Everything else follows.
- **Gotchas:** the build-time value must stay the default so the simulator, emulator and
  desktop keep working untouched. `DEFAULT_LOCAL_API_BASE_URL` is `localhost` and Android
  deliberately does not use it (`10.0.2.2` instead) — do not unify them while here.

## Risks / notes

- **A local override needs a permission, not just a URL.** On Android 17 a root on the local
  network (`10.0.2.2`, RFC1918, CGNAT, an mDNS name) is unreachable without the runtime
  `ACCESS_LOCAL_NETWORK` grant, and the failure is a timeout rather than a refusal — measured,
  and recorded in [`android-local-network-permission.md`](android-local-network-permission.md).
  Keeping the override inside `platformApiBaseUrl` is what keeps it covered by that gate.
- Easy to get wrong: storing the URL where the auth tokens live, or in `DefaultsKey` when
  sign-out clears it. Both are silent — the app simply asks for the server again.
- This task has no server dependency and can land before any of `T9.4`–`T9.10`. Doing so
  is the point: it makes the client ready before the CLI has something to point it at.
