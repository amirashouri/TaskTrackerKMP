# 9.3 — Narrow large test doubles and remove only expired unused-parameter seams

- **status:** pending
- **priority:** P3
- **plan:** none for standalone refactor — this is a housekeeping pass on fakes and intentionally
  unused parameters, not a feature or cross-module cleanup

## Scope

Test doubles and platform entry-point seams in `packages/*/src/...Test` and the platform
`jvmMain`/`iosMain`/`androidMain` entry points that currently carry suppressed or documented
unused parameters.

The only code this task may remove is code that is:
- an intentionally unused test-double method that is no longer needed by the test contract it
  exists for, or
- a suppressed/documented unused parameter whose reason has expired

Anything that is unused only by appearance is out of scope by policy.

## Files

Likely files, to be narrowed at Phase 1 after reading:

- `shared-ui/src/commonTest/kotlin/com/tasktracker/sharedui/ProjectFakes.kt`
- `packages/feature-projects-presentation/src/commonTest/kotlin/com/tasktracker/featureprojectspresentation/FakeProjectRepository.kt`
- any platform entry point that currently suppresses `UNUSED_PARAMETER` purely because the host
  parameter is not needed for its current implementation

Out of scope:
- shrinking test coverage
- merging or deleting tests just because they look large
- removing `@OptIn` uses that are legitimately required by test or coroutine test APIs

## Contract

- [ ] Each removed unused method or parameter was actually unused by the test/presentation contract
      it existed for
- [ ] No fake’s behavior was narrowed in a way that changes any existing test outcome
- [ ] No suppressed unused parameter was removed until its reason was confirmed expired
- [ ] Production code was not touched unless it is the matching production seam for a test-only
      fake change
- [ ] Existing tests still pass with no new blanket suppressions added just to hide the change

## Non-goal

- This task does **not** replace every large fake with smaller ones globally.
- This task does **not** remove intentional seams like the unused-sync-coordinator test helper
  unless that helper’s reason has genuinely expired.

## Validation

- Run: `cd TaskTrackerKMP && ./scripts/check.sh quick`
- Counts: this may change test-file shape without adding new assertions. If test counts shift,
  verify the change is expected before regenerating baseline.
- Because this work is mostly about intent and seams, a behavioral or structural review is more
  useful than a pixel review. The `test-reviewer` subagent is only needed if a visual assertion is
  involved.

## Handoff

- **Done:** expired unused-parameter seams and truly unneeded fake methods removed
- **Pending:** confirm remaining unused-parameter seams are still intentional
- **Next step:** read the biggest fakes and the suppressed unused-parameter sites, then decide which
  ones are genuinely expired instead of just tidy-looking
- **Gotchas:**
  - “Looks unused” is not enough in this codebase; the reason must be expired, not just inconvenient
  - Do not remove a fake method because only one test uses the fake differently; verify the seam is
    actually free to go
  - Do not turn a documented unused parameter into silence by deleting it unless the contract is gone

## Risks / notes

- This is the lowest-priority item on purpose. The value is in reducing future maintenance drift,
  not in a big deletion.
- The easy mistake here is cosmetic cleanup that fights the existing deliberate seams. If a seam has
  a comment explaining why it is unused, the default is to keep it.
