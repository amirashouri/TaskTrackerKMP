# 9.1 — Remove the deprecated WorkItemEditor expand/collapse parameters

- **status:** pending
- **priority:** P1
- **plan:** none for standalone refactor (not part of the active roadmap table yet) —
  this is a cleanup of a deprecated surface that the editor no longer uses

## Scope

The editor's presentation contract in `feature-projects-presentation`, where the
expand/collapse mode is now dead behavior.

If this task touches `feature-projects-domain`, `feature-projects-data`, or any wire
format, that is out of scope and must stop for re-planning.

## Files

- `packages/feature-projects-presentation/src/commonMain/kotlin/com/tasktracker/featureprojectspresentation/workitem/WorkItemEditor.kt`
- anything inside `feature-projects-presentation` that still references the deprecated
  expand/collapse parameters or state

Out of scope for this task:
- any refactoring of `MemberPicker`, project switcher, shell layout, clipboard, or glass

## Contract

- [ ] The editor composable no longer has the deprecated expand/collapse parameters in its
      public surface
- [ ] Every call site inside `feature-projects-presentation` no longer passes the deprecated
      expand/collapse state
- [ ] Nothing outside `feature-projects-presentation` was edited
- [ ] The editor still renders as full-screen after the change
- [ ] Existing editor behavior tests still pass, and no new `ignoreUnknownKeys`-style escape
      was added to keep dead parameters alive

## Non-goal

- This task does **not** change how the editor saves, loads, or syncs work items.
- This task does **not** change the member picker, sprint owner field, or any other picker.

## Validation

- Run: `cd TaskTrackerKMP && ./scripts/check.sh quick`
- Counts: this is a refactor that should not add tests. If any test host regresses, the
  change is too broad. Regenerate baseline only if the change legitimately affects counts,
  and only after that is expected.
- The editor is a behavioral surface; if a pixel or interaction review is warranted, route it
  through the `test-reviewer` subagent before the PR.

## Handoff

- **Done:** remove the deprecated expand/collapse API surface and all internal references to it
- **Pending:** confirm the editor still behaves as always-full-screen after the change
- **Next step:** read the current deprecated parameters and their call sites, then remove the
  smallest set that clears the contract
- **Gotchas:**
  - Do not keep deprecated parameters alive just because other code paths still mention them
  - Do not widen scope to other pickers or the shell
  - If the deprecated surface is still referenced outside `feature-projects-presentation`,
    stop and report the exact file before proceeding

## Risks / notes

- The current deprecation comment says the editor is always full-screen but keeps the old
  parameters. That is the exact shape of a deletion that is waiting on its callers being gone.
- The risk is not architecture; it is accidentally leaving a stale seam in place, or accidentally
  widening the task when it should stay narrowly focused.
