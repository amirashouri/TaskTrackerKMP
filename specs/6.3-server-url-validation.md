## Design decisions

- **The validator allows cleartext for local addresses only.** `https` is accepted for
  any parseable host. `http` is accepted for loopback, `10.0.2.2`, RFC1918,
  link-local, CGNAT and mDNS/single-label names, because the default `lan` provider is
  plain HTTP on the LAN. A public host over `http` is refused. Android's narrower
  cleartext allow-list (`localhost` and `10.0.2.2`) is a separate, documented gate: the
  probe reports the blocked LAN address at pairing time instead of the validator
  pretending Android can reach it.
- **Validation is a pure function; the probe is a port.** `validateServerAddress` has
  no coroutine, network or platform dependency, so its whole table runs on every host.
  `CheckServerAddress` depends only on `ServerAddressProbe`, so its order and failure
  mapping are testable with a fake.
- **The probe seam is one small interface.** `HttpServerAddressProbe` takes a
  `(String) -> ProbeClient` factory; the production client wraps a `KtorHttpClient`
  bound to the candidate address and closes it. Tests inject a fake `ProbeClient` and
  pin the `/healthz` path, `requiresAuth = false` and the `ok` body rule without Ktor.
- **No `SettingsPort` change yet.** 6.2 adds the Settings row and the port method;
  adding it here would force edits to two presentation test fakes and composition-root
  wiring that the archive assigns to 6.2. The rule and probe land first, fully tested.

## Contract

- [ ] `https` with a parseable host and optional port/path is valid.
- [ ] `http` is valid only for a local host (loopback, `10.0.2.2`, RFC1918,
      link-local, CGNAT, `.local`/single-label); a public host over `http` fails with
      `CleartextNotPermitted`.
- [ ] Blank input, a missing scheme, an unsupported scheme, a missing host, userinfo,
      a query/fragment, a bad port or unparseable text fails with a distinct reason —
      none of them throws.
- [ ] The returned `baseUrl` is normalised: surrounding whitespace trimmed, scheme and
      host lower-cased, a trailing slash removed. The path prefix is preserved.
- [ ] `CheckServerAddress` probes only a syntactically valid address, and returns
      `Unreachable` when the probe says it did not answer `ok`.
- [ ] The probe sends `GET /healthz` with `requiresAuth = false` and a short timeout;
      it accepts a trimmed body of exactly `ok` and treats any transport error or
      other body as a failure.
- [ ] Cancellation propagates through both the probe and the use case; no
      `CancellationException` becomes `Unreachable`.
- [ ] Nothing is saved and no UI is added in this task.

## Validation

- Run: `scripts/check.sh full` — two modules, pure and behavioural tests; all three
  hosts must stay green.
- Counts: `test-baseline.json` moves on every host; regenerate with
  `scripts/test-baseline.py` and let `scripts/check-baseline.sh` pass.
- Mutation checks:
  - Make `validateServerAddress` always return `Valid` → the cleartext and malformed
    table fails.
  - Make `CheckServerAddress` skip the probe → the `Unreachable` test fails.
  - Drop the `ok` comparison in the data probe → the wrong-body test fails.
- Structural and behavioural assertions only; the `test-reviewer` subagent is not
  required.

## Risks / notes

- The local-host spelling rules overlap `composition-root`'s
  `apiRootRequiresLocalNetworkAccess`, but the policies differ: that one deliberately
  excludes loopback (no permission prompt behind it) and this one includes it
  (cleartext is fine). Sharing the parser would be a cross-module refactor outside
  this task; the tests pin both tables.
- A hostname that resolves to a local address (`nas.tailnet.ts.net`) is classified
  remote from its spelling. The probe is what catches it, which is exactly why the
  probe is part of this task.
- The probe opens a second HTTP client for the candidate root; it exists only for the
  duration of the check and is closed in `finally`. The app-scoped client is bound to
  the current root and cannot be reused.
- `lan` over plain HTTP still does not work on Android; the probe will report the
  blocked address. That is documented, not worked around.
